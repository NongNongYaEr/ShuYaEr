## 这与通行的“开源”有什么区别

拟定方案限制修改版的发行和销售，因此应称为“免费使用、源码公开”，不标注为 OSI 开源。标准开源定义要求允许再分发和衍生作品；MIT、Apache、GPL 等许可证不能通过追加一句“禁止售卖修改版”就仍然按原许可证运作。

GitHub 公共仓库的查看和平台内 Fork 仍按 GitHub 服务条款处理。不能把平台允许的 Fork 本身一概视为违规，也不能把 Fork 当作获得站外发行或销售授权的证明。

## 关于拟议的责任金额

软件修改版违规发行／销售拟议违约金为 **100 万元**，素材违规转售拟议违约金为 **10 万元**。这些金额尚待审阅，**不是平台有权开出的罚款，不是自动生效或保证法院支持的最低赔偿额**。有效合同、条款提示、损失及具体事实均会影响认定；依法可以请求调整违约金。

侵权责任与合同责任分别依法判断，不能靠一段 README 让全部访客自动承担高额违约金。

不合理加重使用者责任的格式条款还可能无效，不能只认为“签了就有效，最多调低金额”。单独勾选也不当然修复不公平的条款。正式方案应以可证明的权利、违规事实和损失为基础。

## 授权期限与商业作品

有效会员期间合法领取的素材版本，正常到期后可继续用于新旧商业项目，无需仅为继续使用而续费。未来更新、其他未领取素材和到期重新发放网盘链接不自动包括在内。

销售成品游戏、影视、效果图与转售素材原文件分别处理；将素材改名、转格式再卖成素材包，不因作过修改而自动获得销售资格。向客户或团队移交包含素材的可编辑源工程，其授权边界仍待明确。

## 如何申请授权或处理争议

修改版软件发行、素材原文件销售等超出一般许可的用途，需要明确的单独书面授权。申请应说明申请者、版本、用途、渠道、是否收费与期限；自动回执或未回复不代表同意。

对涉嫌侵权的行为，核实权属、行为、版本及证据后通知，允许说明、提供授权证明与合理纠正；必要时依法主张救济。不以未经核实的举报直接认定违约，也不任意追缴或删除无关作品。具体流程与资料模板见 [发布与授权资料](licensing-release-kit.md)。
